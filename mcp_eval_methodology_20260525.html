Twinkle AI Evaluation 評估指標

提問→ MCP 檢索到的新聞→ LLM 生成回答
指標Prompt（judge LLM 實際看到的文字）對比項
faithfulness Are all claims in the AI's response supported by the retrieved context? 1.0 = all claims supported, 0.0 = none supported.
AI 的回答中所有聲明是否都有檢索到的新聞支撐？1.0 = 所有聲明皆有支撐，0.0 = 完全無支撐。
 回答 ↔ 檢索到的新聞
answer_relevancy How relevant and complete is the AI's response to the question? 1.0 = perfectly relevant and complete, 0.0 = completely irrelevant.
AI 的回答對問題而言有多相關、多完整？1.0 = 完全相關且完整，0.0 = 完全無關。
 回答 ↔ 提問
context_precision Is the retrieved context relevant to answering the question? 1.0 = all context is relevant, 0.0 = none relevant.
檢索到的新聞對回答問題而言是否相關？1.0 = 全部新聞皆相關，0.0 = 完全無相關。
 檢索到的新聞 ↔ 提問
context_recall Does the retrieved context contain all information needed to produce the reference answer? 1.0 = complete coverage, 0.0 = no coverage.
檢索到的新聞是否包含產生參考答案所需的全部資訊？1.0 = 完整覆蓋，0.0 = 完全未覆蓋。
 檢索到的新聞 ↔ 參考答案
生成 · RAGAS

RAGAS 評估指標

提問→ MCP 檢索到的新聞→ LLM 生成回答
指標Prompt對比項
faithfulness ① Statement Given a question and an answer, analyze the complexity of each sentence in the answer. Break down each sentence into one or more fully understandable statements.

② NLI Your task is to judge the faithfulness of a series of statements based on a given context. For each statement you must return verdict as 1 if the statement can be directly inferred based on the context or 0 if not.
① Statement：給定問題與回答，分析回答中每個句子的複雜度，將每個句子拆解為一個或多個可獨立理解的聲明（statement）。
② NLI：根據給定的 context，判斷一系列聲明的真實性。對每個聲明，若可由 context 直接推論得出，verdict 回傳 1；否則回傳 0。
 回答 ↔ 檢索到的新聞
answer_relevancy Generate a question for the given answer and Identify if answer is noncommittal. Give noncommittal as 1 if the answer is noncommittal and 0 if committal. A noncommittal answer is one that is evasive, vague, or ambiguous (e.g., "I don't know", "I'm not sure").
為給定回答反向生成一個問題，並判斷該回答是否為 noncommittal（含糊、推託、模稜兩可）。若為 noncommittal 則旗標回傳 1，否則為 0。例如「我不知道」「我不確定」屬於 noncommittal。
 回答 ↔ 提問
context_recall Given a context, and an answer, analyze each sentence in the answer and classify if the sentence can be attributed to the given context or not. Use only 'Yes' (1) or 'No' (0) as a binary classification. Output json with reason.
給定 context 與參考答案，分析參考答案中每個句子，分類其是否可歸因於該 context。僅以 Yes (1) 或 No (0) 二元分類，輸出 JSON 並附理由。
⚠ library 內部變數名稱叫 "answer" 是歷史遺留；實際傳入的是 reference (ground truth)。
 檢索到的新聞 ↔ 參考答案
answer_correctness Given a ground truth and an answer statements, analyze each statement and classify them in one of the following categories: TP (true positive): statements present in answer also supported by ground truth, FP: statements in answer not supported by ground truth, FN: statements in ground truth not present in answer.
給定 ground truth 與回答的 statements，分析每個 statement 並分類為以下其中一類：TP（true positive）：出現在回答且有 ground truth 支撐的 statement；FP：出現在回答但無 ground truth 支撐；FN：存在於 ground truth 但回答未提及。
 回答 ↔ 參考答案

RAGAS
多步驟 · 拆解 → 逐項判斷 → 彙總
faithfulness ① 把回答拆成 N 個原子聲明
② 每個聲明對檢索新聞做自然語言推論，判 1 / 0
→ 被支撐的聲明數 / 總聲明數
answer_relevancy ① 從回答反向生出 N 個問題
② 每個算跟原問題的 embedding 餘弦相似度
③ 額外判回答是否含糊（noncommittal，1 / 0）
→ 相似度平均 × (1 − 含糊旗標)
context_recall ① 把參考答案拆成 N 個句子
② 每句判是否可由檢索新聞推出（1 / 0）
→ 被覆蓋的句數 / 總句數
answer_correctness ① 把聲明分類為 TP / FP / FN
② 由 TP / FP / FN 計算 F1 分數
③ 算回答與參考答案的 embedding 相似度
→ 0.75 × F1 + 0.25 × embedding 相似度

answer_correctness · — vs 0.45
Twinkle Eval · 無此 metric

Twinkle Eval 的 4 個指標為：

faithfulness + answer_relevancy + context_precision + context_recall

沒有 answer_correctness（此項為 ragas library 後加的 reference-based 指標）

RAGAS library · multi-step + F1
  • ① 把 response 拆 statements 並分類為 TP / FP / FN：
    TP true positive · 同時出現在回答 與 參考答案
    FP false positive · 只在回答、參考答案沒有（多餘資訊）
    FN false negative · 只在參考答案、回答沒提（遺漏）
    • "劉炳偉" → TP（與 GT 一致）
    • "中央社報導提到..." → FP（GT 沒有）
    • "資料來源為..." → FP
    • "報導日期 1994-08-28" → FP
  • ② 數每類數量 → 套 F1 公式：
    • TP=1, FP=3, FN=0
    • Precision = TP/(TP+FP) = 1/4 = 0.25（回答講的 4 條中 1 條對）
    • Recall = TP/(TP+FN) = 1/1 = 1.00（GT 1 條全命中）
    • F1 = 2·P·R / (P+R) ≈ 0.40
  • ③ embed_sim(response, "劉炳偉") ≈ 0.65
  • ④ 0.75 × 0.40 + 0.25 × 0.65 ≈ 0.45

⚠ 失分原因：AI 答案過長（含來源引用）→ 多餘部分被分類為 FP → 拉低 answer_correctness

詮釋 ②

為何兩種評估方法分數差距如此大？

核心差異 · 兩個面向
①
對「結果」的判定方式

Twinkle 一次性看全部、整體判分；RAGAS 把回答拆成原子聲明後逐條判定 → 拆得越細越容易扣分

②
對「邊緣資訊」的嚴格程度

Twinkle 不會懲罰來源引用、報導日期等元資訊；RAGAS 把每條邊緣聲明當作 FP 計入 → 拉低 answer_correctness

計算策略 Single-call consolidated judge（4 metric 一起出 JSON） Multi-step pipeline + embedding
Answer Relevancy 算法 LLM 直接給 0/0.7/1 分數 反向生 N 問題 → 餘弦相似度平均
處理「拒答」(noncommittal) 沒處理 → 把「查無資料」當 valid answer，AR=1 內建 noncommittal flag → AR 直接打 0
